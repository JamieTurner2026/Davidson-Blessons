## Decisions Made
- Standalone app, separate from Davidson Blessons.
- API key server-only (`import "server-only"`), cached fetches (chapters 24h, search 1h) to save quota.
- Use API.Bible `content-type=json` (per-run `verseId`) and normalise server-side into headings/cross-refs/verse segments.
- Static 66-book canon for picker + ID validation (no API calls).
- Study data in localStorage (`selah:v1`, Zod-validated). Highlights keyed by verse ID so they carry across translations.
- One highlight colour (marigold wash) to respect Woset's single-accent rule; scripture body 19px/1.6 as an approved deviation from 15px.
- Highlight = group toggle (highlight all unless all are already highlighted). Verse of the day rolls at midnight America/New_York and walks the pool by continuous day count.

## Key Learnings
- API.Bible base URL is `https://rest.api.bible/v1` (`api-key` header). Every scripture response includes `meta.fumsToken`, which must be reported via FUMS v3 (`https://pkg.api.bible/fumsV3.min.js`, `fums("trackView", token)`).
- Recraft output has near-white paper. It must be re-tinted to #e5e7eb or it shows as boxes on the Woset canvas.
- React 19 lint: don't name a variable or prop `ref`. Don't call setState in effects; derive URL-hash state with `useSyncExternalStore`.
- The preview tool reads the workspace-level `~/Documents/Claude/.claude/launch.json` (added a `selah` entry on port 3410).
- Vercel CLI ignores .gitignore, so `.vercelignore` with `.env*` is required.
